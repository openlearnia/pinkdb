pinkdb — a mini DuckDB in Rust

Link it into your program or run the CLI: columnar vectors, vectorized execution, SQL with joins, CTEs and window functions, CSV import, durable .pink files with a write-ahead log, a lake layer over local disk or S3/R2, and C, Python and Go bindings. The default build is ~2.4 MB — zero async in the core, zero unsafe outside the FFI and extension-loader crates.

What it is

pinkdb is an embeddable analytical SQL engine written in Rust, in the spirit of DuckDB: in-process, columnar, vectorized, with a small dependency footprint and no server required. It ships as a library crate (pinkdb), a CLI REPL (pinkdb-cli, a thin consumer of the library), a network server (pinkdb-server) and a C ABI (pinkdb-ffi).

Capabilities are opt-in cargo features, so you only pay for what you use: the default build is 2,436,320 B, the pinklake build adds the .lake commands for 2,692,464 B, and the vortexlake build with the Vortex format is 45,333,984 B. Nothing extra is compiled unless asked for — no crypto, TLS or format code in the default binary.

honest by design

The SQL surface is deliberately small and growing in the open. Everything listed here is implemented and tested; what is queued lives on the roadmap, and the engineering log on GitHub has the detail.

Features

  • Embeddable engine

    Link the pinkdb crate and run SQL in-process. No daemon, no runtime dependencies, ready for embedding.

  • Vectorized columnar core

    Typed column vectors and ≤2,048-row chunks; every operator runs over whole chunks, in parallel via rayon.

  • CSV import

    One command infers the schema per column, parses files in parallel, and auto-detects DATE and TIMESTAMP.

  • Durable .pink files

    Single-file v5 columnar format with delta, dictionary, ALP and LZ encodings, constraint metadata and DECIMAL/INTERVAL; bit-exact round trips and a CRC-32 guard.

  • WAL & crash recovery

    A durable open replays the write-ahead log, checkpoints atomically, and recovers an interrupted checkpoint on the next open.

  • Multi-process writers

    Any local process may open a durable database read-write; writers serialize on a short-held write lease, readers never block, and optimistic commits abort or retry conflicting ones.

  • Lake layer

    Decoupled metadata: a JSON catalog plus immutable per-version manifests; incremental commits that append files instead of rewriting tables, writable attachments, and time travel over published versions. Vortex or .pink data files.

  • S3 / R2 object storage

    An s3:// lake over AWS S3, Cloudflare R2 or any S3-compatible endpoint, with conditional-write conflict detection.

  • Read-only attach

    .lake attach opens a published snapshot without decoding column data; exact COUNT/MIN/MAX come from stored statistics.

  • Network server

    pinkdb-server over TCP with a compact framed protocol and a remote CLI mode — one thread per connection, no async runtime.

  • C · Python · Go bindings

    A C ABI v1 (pinkdb-ffi) with a hand-written header, plus dependency-free Python and Go wrappers, and Rust natively.

  • Loadable extensions

    Register scalar SQL functions from a shared library at runtime — or .install one from the extension catalog.

  • At-rest encryption

    Optional PINKENC1 containers: AES-256-GCM with Argon2id passphrase derivation, for checkpoints and the WAL.

  • SQL surface

    DDL/DML, inner/outer/full/cross and multi-way joins, CTEs, subqueries, window functions, aggregates, DECIMAL/INTERVAL, declarative keys, prepared statements, transactions and multiple databases per store.

Key facts

FactValue
Binaries default 2.44 MB · pinklake 2.69 MB · vortexlake 45.3 MB (release, Apple Silicon)
Persistence .pink v5 single-file columnar format; 1M rows → 2.68 MB, 10M rows → 26.8 MB
SQL CSV import, full/multi-way joins, CTEs, subqueries, window functions, aggregates, DECIMAL/INTERVAL, keys, prepared statements, CAST, dates; transactions and multi-database sessions
Durability write-ahead log + atomic checkpoints; durable databases are multi-process with optimistic commits, and a 5 s busy timeout for writers
Lake incremental commits (append-only files + positional deletes), time travel and per-version records; Vortex or .pink data files; read-only attach answers exact COUNT/MIN/MAX
Object storage s3:// locations on AWS S3, Cloudflare R2 or any S3-compatible endpoint (opt-in s3 feature)
Bindings Rust (native), C (ABI v1), Python (ctypes, no dependencies), Go (cgo)
Extensions loadable native scalar functions (ABI v1), C and Go SDKs, and a hosted extension catalog
DuckDB parity differentially tested against DuckDB on a committed query corpus; the current corpus matches on both engines

Quickstart

Shell
cargo build --release -p pinkdb-cli
./target/release/pinkdb
SQL
.import sales.csv sales
SELECT region, AVG(total) FROM sales GROUP BY region ORDER BY 2 DESC;
Output
┌─────────┬────────────┐
│ region  │ avg(total) │
│ VARCHAR │ DOUBLE     │
├─────────┼────────────┤
│ west    │ 175.0      │
│ east    │ 50.5       │
└─────────┴────────────┘
2 rows
Run Time (s): real 0.000
