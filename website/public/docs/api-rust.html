APIs

Rust API

The native interface: the pinkdb crate for the engine and pink-lake for the lake layer. Everything else — the CLI, server, C ABI and bindings — is built on these types.

Getting the crate#

TOML
[dependencies]
pinkdb = { path = "crates/pinkdb" }        # the engine
pink-lake = { path = "crates/pink-lake" }  # optional: the lake layer

The crates live in this workspace; the examples here use path dependencies. The default build links no crypto, TLS or format code; features opt in:

FeatureAdds
encryptionPINKENC1 at-rest encryption (AES-256-GCM + Argon2id)
vortex-format (on pink-lake)the Vortex lake data format (the CLI's lake feature enables it)
s3 (on pink-lake)S3/R2 object storage (implies the lean lake)

Quick start#

Rust
use pinkdb::PinkDb;

let mut db = PinkDb::new();
for result in db.execute(
    "CREATE TABLE t (a INTEGER, s VARCHAR);\
     INSERT INTO t VALUES (1, 'one'), (2, NULL);\
     SELECT a, s FROM t ORDER BY a;",
)? {
    println!("{result:?}");
}

Public types#

The crate root re-exports the main surface:

Rust
pub use pinkdb::{
    // core session + store
    PinkDb, DataTable, ViewDef,
    // multi-writer handles
    Database, Connection,
    // results and values
    QueryResult, Value, DataType, PinkDbError,
    // vectors
    Vector, VectorData, DataChunk, CHUNK_SIZE,   // CHUNK_SIZE = 2048
    // durability
    DurableOpenOptions, LockMode, RecoveryInfo, SyncPolicy,
    DEFAULT_AUTO_CHECKPOINT_BYTES,               // 64 MiB
    // encryption (feature `encryption`)
    EncryptionKey,
    // attached lakes (CLI/library attach support)
    AttachedLake, AttachedTable, AttachedScan, ColumnStats,
};

Modules: pinkdb::csv (CSV import), pinkdb::sql (parser, AST, binder), pinkdb::plan, pinkdb::optimizer, pinkdb::exec, pinkdb::persist (.pink save/open), pinkdb::wal, pinkdb::db, pinkdb::storage, pinkdb::types, pinkdb::vector, pinkdb::attached.

PinkDb — the engine#

One struct owns an in-memory store and a session (its current database). This is the single-connection embedding API:

Rust
impl PinkDb {
    pub fn new() -> Self;
    pub fn execute(&mut self, sql: &str) -> Result<Vec<QueryResult>>;

    // databases and transactions
    pub fn current_db(&self) -> &str;
    pub fn list_databases(&self) -> Vec<String>;
    pub fn create_database(&mut self, name: &str) -> Result<()>;
    pub fn drop_database(&mut self, name: &str) -> Result<()>;
    pub fn use_database(&mut self, name: &str) -> Result<()>;
    pub fn begin(&mut self) -> Result<()>;
    pub fn commit(&mut self) -> Result<()>;
    pub fn rollback(&mut self) -> Result<()>;
    pub fn in_transaction(&self) -> bool;

    // persistence
    pub fn save(&self, path: &str) -> Result<()>;
    pub fn save_snapshot(&self, path: &str) -> Result<()>;
    pub fn open(path: &str) -> Result<PinkDb>;
    pub fn open_durable(path: &str) -> Result<PinkDb>;
    pub fn open_durable_with(path: &str, policy: SyncPolicy)
        -> Result<(PinkDb, RecoveryInfo)>;
    pub fn open_durable_with_options(path: &str, opts: DurableOpenOptions)
        -> Result<(PinkDb, RecoveryInfo)>;
    pub fn checkpoint(&mut self) -> Result<()>;
    pub fn flush_wal(&mut self) -> Result<()>;
    pub fn durable_path(&self) -> Option<PathBuf>;
    pub fn set_busy_timeout(&self, timeout: Duration);
    pub fn set_auto_checkpoint_bytes(&self, bytes: Option<u64>);

    // encryption (feature `encryption`)
    pub fn save_with_key(&self, path: &str, key: &EncryptionKey) -> Result<()>;
    pub fn open_with_key(path: &str, key: &EncryptionKey) -> Result<PinkDb>;
    pub fn open_durable_with_key(path: &str, key: &EncryptionKey) -> Result<PinkDb>;
    pub fn set_encryption_key(&mut self, key: Option<EncryptionKey>);

    // extensions
    pub fn load_extension(&mut self, path: &str) -> Result<String>;
}

There are more helpers (create_table, drop_table, list_tables, create_view, table_version, and their *_in(db) variants) — see the crate docs. Tables/views are also reachable as DataTable / ViewDef if you build or inspect the store directly.

Importing CSV

Rust
use pinkdb::csv;

csv::import_csv(&mut db, "sales.csv", Some("sales"))?;        // file -> table
csv::import_csv_string(&mut db, "t", "a,b\n1,x\n")?;          // text -> table

Durable options

Rust
use pinkdb::{DurableOpenOptions, LockMode, SyncPolicy};
use std::time::Duration;

let opts = DurableOpenOptions {
    policy: SyncPolicy::Sync,              // fsync every record (or SyncPolicy::Batch)
    busy_timeout: Duration::from_secs(5),  // wait for another process's write lease
    lock_mode: LockMode::Required,         // fail closed when locking is unsupported
};
let (db, recovery) = PinkDb::open_durable_with_options("x.pink", opts)?;
println!("{} records replayed", recovery.replayed_records);

Database / Connection — multi-writer#

Database wraps the store in shared locks for multi-connection use (one Connection per thread); durable opens through it also carry the WAL and, for local files, the multi-process write lease.

Rust
use pinkdb::Database;

// in memory
let db = Database::new();

// durable
let db = Database::open("x.pink")?;
let db = Database::open_with_options("x.pink", opts)?;

let mut c = db.connect();
c.execute("CREATE TABLE t (a INTEGER);")?;

db.checkpoint()?;                    // SQL `CHECKPOINT` also works from any front-end
db.set_busy_timeout(Duration::from_secs(10));
db.set_auto_checkpoint_bytes(Some(64 * 1024 * 1024));

EncryptionKey#

Rust
use pinkdb::EncryptionKey;

let key = EncryptionKey::from_passphrase("correct horse battery staple");
// or a raw 32-byte key — see the type's constructors.

db.save_with_key("x.pink", &key)?;
let db = PinkDb::open_durable_with_key("x.pink", &key)?;

pink-lake#

Rust
use pink_lake::{Lake, save_store, save_store_url};

let version = save_store(&db, "mylake")?;        // create + save
let mut lake = Lake::open("mylake")?;            // or Lake::open_url("s3://…") with `s3`
let v = lake.write_from_store(&db)?;             // publish a new full snapshot
let versions = lake.versions()?;                 // [1, 2, 3]
let tables = lake.tables()?;                     // [("main.t", 2)]
let db = lake.load(None)?;                       // rebuild the latest version
let db = lake.load(Some(2))?;                    // or a specific one
let report = lake.attach(None)?;                 // read-only attachment (statistics)
// save_store_s3 / save_store_url for object storage
// S3Config::new(bucket).with_prefix(..).with_region(..)
//     .with_endpoint(..).with_credentials(..) for explicit configuration

One live writer handle per lake; loads and attachments can run concurrently from published versions. Details on the Lake page.

How the engine works#

  • Pipeline: SQL text → AST → binder (types, tables, columns) → logical plan → optimizer (predicate pushdown, constant folding) → vectorized executor → columnar storage.
  • Vectors, not rows: a Vector is a typed column chunk plus a validity bitmask; operators exchange DataChunks of ≤2,048 rows. WHERE produces a selection vector instead of copying rows.
  • Parallel by default: queries run under a shared read lock with rayon-parallel chunks; writes take the write lock per statement; transactions use snapshot isolation with write-conflict detection.
  • Design rules: Rust edition 2021, zero async in the core, no unsafe outside pinkdb-ffi and pinkdb-ext-loader; new capabilities arrive as separate crates or opt-in features.
