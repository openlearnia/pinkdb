Guide: embedding pinkdb

Add a SQL engine to your application from Rust, C, Python or Go. This guide gets each target to "open a database, run SQL, read typed results".

Rust (native)#

Rust
use pinkdb::{Database, PinkDb};

// single connection, simplest possible:
let mut db = PinkDb::new();
let results = db.execute(
    "CREATE TABLE events (name VARCHAR, n BIGINT);\
     INSERT INTO events VALUES ('signup', 3), ('login', 9);\
     SELECT name, SUM(n) AS total FROM events GROUP BY name ORDER BY total DESC;",
)?;
println!("{results:?}");

// multi-threaded host: one shared store, one Connection per thread
let db = Database::new();
let mut c = db.connect();
c.execute("SELECT 1;")?;

For durable files, use Database::open, PinkDb::open_durable or the encryption variants — the same machinery the CLI uses. See the Rust API.

C / C++#

Shell
cargo build --release -p pinkdb-ffi
# link: -L target/release -lpinkdb_ffi
# include: crates/pinkdb-ffi/include/pinkdb.h
C
#include "pinkdb.h"

pinkdb_handle *db = pinkdb_open_memory();
const char *sql =
    "CREATE TABLE t (x INTEGER);"
    "INSERT INTO t VALUES (42);"
    "SELECT x FROM t;";

pinkdb_result *r = pinkdb_execute(db, sql, strlen(sql));
if (!r) { fprintf(stderr, "%s\n", pinkdb_last_error()); return 1; }

pink_value v = pinkdb_result_value(r, 2, 0, 0);   /* statement 2, row 0, col 0 */
printf("%lld\n", (long long)v.int64);             /* 42 */

pinkdb_result_free(r);
pinkdb_close(db);

Handles are not thread-safe — one per thread, or serialize calls. VARCHAR pointers borrow from the result; copy with text_len (embedded NULs are allowed). Full details: C API.

Python#

Shell
cargo build --release -p pinkdb-ffi
python3 -c "import pinkdb"      # resolves the library from the repo checkout
Python
import pinkdb

with pinkdb.connect("app.pink") as db:         # durable; or connect_memory()
    db.execute("CREATE TABLE t (x INTEGER);")
    db.execute("INSERT INTO t VALUES (42);")
    result = db.execute("SELECT x FROM t;")[0]
    print(result.kind, result.rows)            # selected [[42]]

A Database is safe to share between threads (calls are serialized internally). A pip-installable wheel is planned. See the Python API.

Go#

Shell
cargo build --release -p pinkdb-ffi

# from your app, point the module at your pinkdb checkout
# (a standalone published module is planned):
go mod edit -replace github.com/openlearnia/pinkdb/bindings/go=/path/to/pinkdb/bindings/go
Go
import pinkdb "github.com/openlearnia/pinkdb/bindings/go"

db, err := pinkdb.Open("app.pink") // or pinkdb.OpenMemory()
if err != nil {
    log.Fatal(err)
}
defer db.Close()

results, err := db.Execute("CREATE TABLE t (x INTEGER); INSERT INTO t VALUES (42); SELECT x FROM t;")
if err != nil {
    log.Fatal(err)
}
rows := results[len(results)-1].Rows // [[42]]

One *DB is safe to share between goroutines. See the Go API.

Choosing an embedding#

SituationUse
Rust application the pinkdb crate directly — no ABI, full API (durability options, encryption keys, lake)
C/C++ or another FFI language pinkdb-ffi (ABI v1); the header is the contract
Python scripts and tools bindings/python (stdlib ctypes, no pip)
Go services bindings/go (cgo, goroutine-safe wrapper)
Several processes on one file the durable path — all embeddings open the same WAL/lease machinery
Feature note

The C ABI builds the engine without CLI features: encrypted databases and lake commands are Rust/CLI paths today. The bindings inherit that and open plaintext databases.
