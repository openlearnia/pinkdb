CLI & REPL

pinkdb-cli is a thin consumer of the library: a rustyline REPL with dot-commands and DuckDB-style box-drawn output. The release binary is named pinkdb.

Build and run

cargo run -p pinkdb-cli                       # debug REPL
cargo build --release -p pinkdb-cli
./target/release/pinkdb                       # local (embedded) mode
cargo build --release -p pinkdb-cli --features client
./target/release/pinkdb --host 127.0.0.1:5433 # remote mode

You land at the pinkdb> prompt. SQL statements run until a semicolon (a ...> continuation prompt appears while one is open); dot-commands are single-line and take no semicolon.

Dot-commands

CommandDescription
.help show the dot-command help (a shorter list in remote mode)
.quit / .exit leave the shell
.databases list databases; the current one is marked and table/view counts are shown separately — main (current) (2 tables, 1 view)
.tables list tables (with row counts) and views of the current database
.schema <table|view> show a schema; accepts db.table, views show their output columns, double-quoted identifiers with spaces work ("My Db".t)
.import <file.csv> [table] import a CSV; the table defaults to the file stem, and a db.table target names another database when db exists
.save <file.pink> write a checkpoint when the path is the bound database, otherwise a plain snapshot (refused when the target has a sidecar WAL with committed records)
.open <file.pink> open durably: load the checkpoint, recover an interrupted checkpoint, replay the sidecar WAL, and replace the whole store

For .import, a dotted target is db.table only when the left side names an existing database — otherwise the whole string is the table name, so a file stem like data.2024.csv imports as data.2024. .tables and .schema scope to the current database; USE <db> switches it.

Output and timing

Results are box-drawn with a type row, then a row count and a timing line:

┌─────────┬────────────┐
│ region  │ avg(total) │
│ VARCHAR │ DOUBLE     │
├─────────┼────────────┤
│ west    │ 175.0      │
│ east    │ 50.5       │
└─────────┴────────────┘
2 rows
Run Time (s): real 0.000

At most 10 000 rows are printed; longer results end with a (N more rows) note.

Environment variables

VariableEffect
PINKDB_PARSER=legacy use the hand-written lexer + recursive-descent parser instead of the default PEG grammar. Both parsers are differential-tested to accept the same inputs with equal ASTs (error messages differ).
PINKDB_KEY passphrase for at-rest encryption: .save writes encrypted and .open decrypts (the durable WAL uses the same key). Requires a build with the encryption feature. A set-but-non-UTF-8 value is a hard error (exit 2) instead of a silent fallback to plaintext. 
cargo build --release -p pinkdb-cli --features encryption
PINKDB_KEY='correct horse battery staple' ./target/release/pinkdb

Remote mode

With the optional client feature, --host HOST:PORT sends every SQL statement to a pinkdb-server and renders results with the same renderer and timing line. SQL (including USE, CREATE DATABASE, and transactions) works unchanged; the file and catalog dot-commands (.import, .save, .open, .databases, .tables, .schema) are not available and report Error: <cmd> is not available in remote mode. Without the feature, --host is rejected with “built without the client feature”. PINKDB_KEY is inert in remote mode and is reported as a warning.
