C API

The pinkdb C ABI v1, exported by pinkdb-ffi as libpinkdb_ffi.dylib / libpinkdb_ffi.a. The header is crates/pinkdb-ffi/include/pinkdb.h and is the complete contract; this page mirrors it.

Build and link

cargo build --release -p pinkdb-ffi     # cdylib + staticlib into target/release/
make -C crates/pinkdb-ffi hello         # compiles and runs the C example

Link with -lpinkdb_ffi and include crates/pinkdb-ffi/include/pinkdb.h. The header is plain C99 and C++ safe (extern "C" guards).

Types

typedef struct pinkdb_handle pinkdb_handle;   /* opaque */
typedef struct pinkdb_result pinkdb_result;   /* opaque */

/* One result value, passed by value. `int64` carries BOOLEAN (0/1), INTEGER,
 * BIGINT, DATE (days since epoch) and TIMESTAMP (microseconds since epoch).
 * `double_` carries DOUBLE. `text_ptr`/`text_len` carry VARCHAR (with a
 * trailing NUL at text_ptr[text_len]). When `is_null` is non-zero only
 * `type_tag` is meaningful. */
typedef struct pink_value {
    int32_t type_tag;
    int32_t is_null;
    int64_t int64;
    double double_;
    const char *text_ptr;
    size_t text_len;
} pink_value;

Contract

  • Ownership. Every pointer returned by the library is freed with the matching function (pinkdb_result_free, pinkdb_close); never free the same pointer twice.
  • Text lifetimes. Text pointers borrow from their owning result/handle/thread and stay valid only until that owner is freed or the next FFI call on the same thread — copy them if you need them longer. text_ptr is followed by a NUL byte but may contain embedded NULs: always trust text_len.
  • Threading. Handles are not thread-safe; never call into one handle from two threads at once (serialize calls, e.g. with a mutex — the Python and Go bindings do). Errors are thread-local.
  • SQL input. Passed as (pointer, length) and must be valid UTF-8. A NULL pointer with a non-zero length, or invalid UTF-8, is an error.
  • Error reporting. Functions returning a pointer return NULL on failure; index/kind accessors return 0/-1 for out-of-range; read pinkdb_last_error() for the message.
  • Durability. pinkdb_open opens the embedded durable path — the same WAL, checkpoint and multi-process write-lease machinery as the CLI (see Persistence).

Example

#include "pinkdb.h"
#include <stdio.h>
#include <string.h>

int main(void) {
    pinkdb_handle *db = pinkdb_open_memory();
    const char *sql =
        "CREATE TABLE t (id BIGINT, name VARCHAR);"
        "INSERT INTO t VALUES (1, 'one'), (2, NULL);"
        "SELECT id, name FROM t ORDER BY id;";

    pinkdb_result *result = pinkdb_execute(db, sql, strlen(sql));
    if (!result) { fprintf(stderr, "%s\n", pinkdb_last_error()); return 1; }

    const size_t stmt = 2;  /* the SELECT */
    size_t rows = pinkdb_result_row_count(result, stmt);
    printf("%zu rows\n", rows);
    for (size_t r = 0; r < rows; r++) {
        pink_value id = pinkdb_result_value(result, stmt, r, 0);
        pink_value name = pinkdb_result_value(result, stmt, r, 1);
        printf("%lld %.*s\n", (long long)id.int64,
               (int)name.text_len, name.text_ptr ? name.text_ptr : "");
    }

    pinkdb_result_free(result);
    pinkdb_close(db);
    return 0;
}

Not exposed through the C ABI today: at-rest encryption keys (pinkdb_open takes only a path) and extension installation. Use the Rust API or the CLI for encrypted databases; a column identifier containing a NUL byte is truncated in the names this ABI reports back (the engine keeps the full name).
