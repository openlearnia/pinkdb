Getting started

Build pinkdb, import a CSV, run your first analytical queries, and save the result to a durable .pink file — about five minutes end to end.

Prerequisites

A recent stable Rust toolchain (the workspace uses edition 2021). The core crates build on Rust 1.89; the lake crate (pink-lake) requires 1.95. Python 3 is only needed for the benchmark helpers and this site's generator.

git clone https://github.com/openlearnia/pinkdb
cd pinkdb
debug vs release

The debug REPL is fine for first steps. All sizes and timings in these docs come from release builds (cargo build --release).

Build and run the REPL

  1. Start the debug REPL straight from the workspace:

    cargo run -p pinkdb-cli

    You land at the pinkdb> prompt. Statements run until a semicolon; a continuation prompt ( ...>) appears while a statement is open.

  2. For day-to-day use, build the release binary:

    cargo build --release -p pinkdb-cli
./target/release/pinkdb

Other opt-in features: encryption adds AES-256-GCM + Argon2id at-rest support (about 70 KB over the default on a thin-LTO release build); repo adds the extension-repository client used by .install (≈+2 MB); client adds the remote REPL mode. The features combine, for example:

cargo build --release -p pinkdb-cli --features lake,s3
cargo build --release -p pinkdb-cli --features lake-lite   # lean lake, local disk
cargo build --release -p pinkdb-cli --features encryption
cargo build --release -p pinkdb-cli --features repo
Optional: a 1M-row practice dataset

The benchmark CSV generator is deterministic (seed 42) and writes sales_1m.csv with columns id, region, total, active:

python3 bench/gen_sales.py            # 1M rows, ~24 MB
python3 bench/gen_sales.py 5000 small.csv

Import a CSV

Create a tiny file and import it. Table names default to the file stem; a db.table argument targets another database when db already exists.

cat > sales.csv <<'EOF'
region,total
west,10.5
east,7.0
north,
EOF
pinkdb> .import sales.csv sales
Imported 3 rows in 0.001s
pinkdb> .schema sales
CREATE TABLE sales (
  region VARCHAR,
  total DOUBLE
); -- 3 rows, 1 chunks

CSV import infers the schema per column over the non-empty cells in the file: all i32 values → INTEGER, all i64 → BIGINT, all floats → DOUBLE, all true/false (case-insensitive) → BOOLEAN, anything else → VARCHAR. An empty cell becomes NULL. Types are sampled from the first 20 480 rows and the import transparently reruns with whole-file inference if a later row disagrees. Files without " or \r bytes are parsed in parallel across the rayon pool.

First queries

SELECT * FROM sales;
SELECT region, AVG(total) AS avg_total, COUNT(*) AS n
  FROM sales
  GROUP BY region
  ORDER BY 3 DESC;
SELECT COUNT(*) FROM sales WHERE total IS NULL;
SELECT region, total * 2 AS doubled
  FROM sales
  WHERE total IS NOT NULL
  ORDER BY doubled DESC
  LIMIT 2;

Results are box-drawn with a type row (DuckDB-style), followed by the row count and a timing line:

┌─────────┬───────────┬────────┐
│ region  │ avg_total │ n      │
│ VARCHAR │ DOUBLE    │ BIGINT │
├─────────┼───────────┼────────┤
│ west    │ 10.5      │ 1      │
│ east    │ 7.0       │ 1      │
│ north   │ NULL      │ 1      │
└─────────┴───────────┴────────┘
3 rows
Run Time (s): real 0.000

Long results are capped at 10 000 displayed rows with a (N more rows) note; the query itself still runs over all of them.

Save and reopen

pinkdb> .save sales.pink
pinkdb> .quit
$ ./target/release/pinkdb
pinkdb> .open sales.pink
pinkdb> SELECT COUNT(*) FROM sales;
┌──────────┐
│ count(*) │
│ BIGINT   │
├──────────┤
│ 3        │
└──────────┘

.save to the open file checkpoints it; .open opens durably — it loads the checkpoint, replays the sidecar sales.pink.wal, and then logs every committed transaction. Durable databases can be opened from several processes at once, and a CHECKPOINT folds the WAL back into the .pink file. The whole story is on the persistence page.

Use it as a library

use pinkdb::PinkDb;

let mut db = PinkDb::new();
pinkdb::csv::import_csv_string(&mut db, "t", "a,b\n1,x\n2,y\n")?;
for result in db.execute("SELECT a, upper(b) FROM t WHERE a > 1;")? {
    println!("{result:?}");
}

The multi-writer API wraps the store in Arc<RwLock<PinkDb>>: one shared store, one Connection per thread, snapshot-isolated transactions.

use pinkdb::Database;

let db = Database::new();
let mut c = db.connect();
c.execute("CREATE TABLE t (a INTEGER);")?;
