SQL reference

The v1 SQL surface, as implemented by pinkdb::sql and the vectorized executor. SQL is parsed by a peg-generated grammar — the PEG path is the only parser.

DDL and DML

CREATE TABLE t (id BIGINT, name VARCHAR, price DOUBLE);
CREATE TABLE db1.t (...);            -- qualified: any db.table target works
INSERT INTO t VALUES (1, 'x', 9.5), (2, NULL, 3.0);
UPDATE t SET price = price * 1.1 WHERE id > 1;   -- SET exprs see pre-update values
DELETE FROM t WHERE price IS NULL;               -- NULL never matches
BEGIN; UPDATE t SET price = 0; ROLLBACK;         -- flat snapshot transactions
CREATE DATABASE db1;                 -- new, empty database
DROP DATABASE db1;                   -- the last database cannot be dropped
USE db1;                             -- per-session current database (default: main)
DROP TABLE t;  DROP VIEW v;
CREATE VIEW v [(cols)] AS SELECT ...;  -- session-local, rebound per use

UPDATE and DELETE are statement-atomic: the statement sees the pre-update values and either applies completely or not at all. BEGIN / COMMIT / ROLLBACK snapshot the whole store: commits to disjoint tables all succeed, and overlapping writes abort the second committer with a write-conflict error instead of a silent lost update.

dml shorthand

SET expressions see the pre-update values, DELETE never matches NULL, and a statement is atomic: all rows or none.

SELECT

SELECT [DISTINCT] expr [AS alias], ...
FROM t [JOIN u ON t.x = u.y]      -- INNER / LEFT [OUTER] / RIGHT [OUTER], equi-join
  | FROM db1.t                    -- qualified tables resolve in that database
  | FROM (SELECT ...) AS s         -- derived tables (alias required)
  | WITH w AS (SELECT ...) ...     -- CTEs, incl. WITH w(a, b) AS column aliases
WHERE expr                        -- IS [NOT] NULL, BETWEEN, IN (subquery|list), EXISTS
GROUP BY ... HAVING ...
ORDER BY expr [ASC|DESC], ...      -- NULLS LAST both ways; ORDER BY 2 positional
LIMIT n;

-- Scalar subqueries (SELECT ...) anywhere an expression goes:
-- uncorrelated only: exactly 1 row × 1 col, 0 rows → NULL.

Joins

  • Equi-joins only, a single equality predicate: INNER, LEFT [OUTER], RIGHT [OUTER].
  • Outer joins NULL-extend the unmatched side's columns; join-kind-aware predicate pushdown.
  • Cross-database joins work: db1.t JOIN db2.u.
  • No FULL joins; CROSS joins are rejected.
  • Integer-key joins use a specialized fast path, and join→aggregate queries are fused so intermediate rows are never materialized (mixed-predicate joins materialize).

Subqueries and CTEs

  • Derived tables in FROM (alias required), including inside CTEs, views, and other subqueries.
  • Scalar subqueries, IN (subquery), and EXISTS (subquery) — uncorrelated only; correlated subqueries are rejected.
  • WITH w AS (...) plus WITH w(a, b) AS (...) column aliases. CTEs shadow unqualified names only; a qualified name never resolves to a CTE.

Set operations and views

  • UNION [ALL|DISTINCT] with numeric type unification. An ORDER BY/LIMIT after the set operation applies to the whole result; branch-level clauses need parentheses and are unsupported in v1.
  • CREATE VIEW v [(cols)] AS ... — session-local and per-database; bodies are self-contained (the caller's CTEs never leak in) and rebound per use.

Aggregates and window functions

  • Aggregates: COUNT(*) / COUNT(x), SUM, AVG, MIN, MAX.
  • Window functions: ROW_NUMBER, RANK, DENSE_RANK, and aggregates OVER with PARTITION BY / ORDER BY / ROWS frames. The default frame is cumulative with ORDER BY and whole-partition without it. No RANGE frames and no nesting.
  • Window functions are allowed in the SELECT list and ORDER BY only (not in WHERE/GROUP BY/HAVING).
  • Aggregates in ORDER BY need a select alias or position; general ORDER BY expressions must be aliases, positions, or GROUP BY keys.

Scalar functions and expressions

  • abs, round (1–2 args), upper, lower, length, substr.
  • CAST(x AS type): the numeric tower both ways, bool↔numeric, varchar parse/format, date↔timestamp; bad input errors.
  • COALESCE(a, b, ...) with a common result type; LIKE/NOT LIKE with %/_ patterns.
  • CASE WHEN c THEN v ... [ELSE e] END and the simple CASE x WHEN v ... form. NULL conditions never match; result types unify like COALESCE.

Date operations: date ± integer adds/subtracts days, date - date yields BIGINT days, and year(x), month(x), day(x), hour(x), minute(x), second(x), and date_trunc(part, x) are available. CSV import auto-detects YYYY-MM-DD as DATE and YYYY-MM-DD HH:MM:SS[.f] as TIMESTAMP.

Coercion rules

  • INTEGER → BIGINT → DOUBLE.
  • int / int → DOUBLE (the DuckDB rule).
  • % is integer-only. Integer overflow is an error, like DuckDB (+/-/*, negation, abs, date ± n, narrowing casts); SUM over integers accumulates in 128 bits and errors only when the final result does not fit BIGINT.
  • Integer division/modulo by zero is an error; 0.0 float division is IEEE.
  • Mixed DATE/TIMESTAMP comparison is rejected; timestamps never mix with integers (no INTERVAL type in v1).

Three-valued logic

  • NULL fails WHERE: a comparison with NULL is never true.
  • COUNT(x), SUM, and AVG skip NULLs; COUNT(*) counts rows.
  • NULL group keys group together.
  • NULL join keys never match.
  • LEFT/RIGHT joins NULL-extend the unmatched side's columns.
  • CASE conditions that evaluate to NULL never match.

Databases and sessions

Databases are named, case-insensitive namespaces (main by default). A session — the embedded PinkDb, or each Connection — has a current database; unqualified table names resolve there. USE db switches it and never affects other sessions: the shared store is untouched.

  • db.table qualifies any table reference in FROM/JOIN, INSERT, UPDATE, DELETE, CREATE TABLE, DROP TABLE, CREATE VIEW, and DROP VIEW.
  • Three-part column references (db.table.col) are not supported — use an alias (SELECT x.col FROM db.table AS x); a clear parse error is returned.
  • Views are per-database and session-local: created in the current database and resolved there, with their bodies resolving unqualified names in that database.
  • DROP DATABASE refuses the last database and switches a session that was using the dropped database to main (or the first remaining database). CREATE/DROP DATABASE are refused inside a transaction.
  • USE, DATABASE, and LEFT/RIGHT/OUTER/FULL/CROSS are reserved words; quote identifiers to use them as names ("use" works).

Known v1 limits

  • No nested transactions or savepoints; one process per .pink path.
  • Durable commits refuse statements that read a session-local view (views are never persisted), and .import checkpoints so it needs a settled transaction.
  • Correlated subqueries are rejected; no FULL joins; CROSS joins are rejected.
  • Expression nesting is capped at 24 levels and the parser-to-AST depth at 64 nodes; deeper input returns a clean Parse error instead of overflowing the stack.
