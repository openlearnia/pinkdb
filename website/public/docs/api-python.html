Python API

The pinkdb Python binding is a thin wrapper over the C ABI, implemented with the standard library ctypes module — no cffi, no pip installs, no build step for the package itself.

Setup

cargo build --release -p pinkdb-ffi

Importing pinkdb finds the shared library in this order: the PINKDB_FFI_LIB environment variable (a full path to the libpinkdb_ffi.dylib / .so / .dll), then the repo-relative target/release/. A missing library, a library without the pinkdb symbols, or an ABI version other than 1 raises pinkdb.Error.

import pinkdb

with pinkdb.connect_memory() as db:            # or pinkdb.connect("data.pink")
    db.execute("CREATE TABLE t (x INTEGER, s VARCHAR);")
    db.execute("INSERT INTO t VALUES (1, 'héllo'), (NULL, NULL);")

    result = db.execute("SELECT x, s FROM t ORDER BY x;")[0]
    print(result.kind)          # 'selected'
    print(result.columns)       # ['x', 's']
    print(result.column_types)  # ['integer', 'varchar']
    print(result.rows)          # [[1, 'héllo'], [None, None]]

Functions

FunctionDescription
connect(path) Open a durable database (checkpoint + WAL) at path (str, bytes or os.PathLike). Returns a Database.
connect_memory() Open a fresh, empty in-memory database.
abi_version() ABI version reported by the loaded library (currently 1).
library_path Path of the loaded libpinkdb_ffi shared library.
Error The exception type for every native failure.

Database

  • execute(sql) — run one or more ;-separated statements; returns a list of Result, one per statement. Raises Error (from pinkdb_last_error) if a statement fails; the handle stays usable afterwards.
  • close() — free the native handle; idempotent. The class is a context manager (with pinkdb.connect(…) as db:) and __del__ is safe.
  • Handles cannot be copied: copy.copy / copy.deepcopy raise TypeError; pickling fails safely.
  • Threading: the C handle is not thread-safe, so Database serializes every call behind an internal lock (ctypes releases the GIL during native calls). Sharing one Database across threads is safe; opening the same file from several threads is not needed.

Result

AttributeContents
kind one of selected, created, inserted, updated, deleted, began, committed, rolledback, created_view, dropped_table, dropped_view, created_database, dropped_database, used, loaded_extension, checkpointed

affected row count for INSERT/UPDATE/DELETE, else 0

Errors

  • pinkdb.Error carries the message from the native library; a failed statement leaves the handle usable.
  • DATE/TIMESTAMP values outside Python's datetime range raise Error naming the raw value, instead of silently wrapping.
  • Strings that are not valid UTF-8 (SQL or paths) are rejected before the native call; connect() rejects an empty path or one containing a NUL byte with ValueError.

Tests

python3 -m unittest discover -s bindings/python/tests -v

# prove the environment override:
PINKDB_FFI_LIB="$PWD/target/release/libpinkdb_ffi.dylib" \
    python3 -m unittest discover -s bindings/python/tests -v

The package lives in bindings/python; a pip-installable wheel is planned (see the roadmap). At-rest encryption is not exposed through the C ABI yet, and the binding inherits that — use the Rust API or the CLI's PINKDB_KEY for encrypted databases.
