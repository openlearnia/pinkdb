APIs

Go API

The pinkdb Go binding is a thin cgo wrapper over the C ABI v1 (bindings/go, module github.com/openlearnia/pinkdb/bindings/go). No third-party dependencies — the Go standard library only.

Setup#

Shell
cargo build --release -p pinkdb-ffi

The #cgo directives resolve the ABI header and target/release relative to the package, so a repo checkout needs no environment variables at build or run time.

Go
import pinkdb "github.com/openlearnia/pinkdb/bindings/go"

db, err := pinkdb.OpenMemory() // or pinkdb.Open("data.pink")
if err != nil {
    panic(err)
}
defer db.Close()

results, err := db.Execute(
    "CREATE TABLE t (x INTEGER, s VARCHAR);" +
        "INSERT INTO t VALUES (1, 'héllo'), (NULL, NULL);" +
        "SELECT x, s FROM t ORDER BY x;")
if err != nil {
    panic(err)
}
fmt.Println(results[2].Kind, results[2].Rows) // selected [[1 héllo] [<nil> <nil>]]

Functions#

FunctionDescription
Open(path string) (*DB, error) Open a durable database (checkpoint + WAL) at path.
OpenMemory() (*DB, error) Open a fresh, empty in-memory database.
(*DB).Execute(sql string) ([]Result, error) Run one or more ;-separated statements; one Result per statement.
(*DB).Close() Free the native handle. Idempotent; a second call is a no-op.
(*DB).ABI() uint32 ABI version reported by the linked library (1); stays callable after Close.

Both open functions check pinkdb_abi_version() first: a library that is not ABI 1 fails with an error naming both versions. Open rejects an empty path or one containing a NUL byte before any native call. SQL that is not valid UTF-8 fails with SQL is not valid UTF-8 and leaves the handle usable.

Prepared statements#

  • (*DB).Prepare(sql) (*Stmt, error) — prepare a single statement; errors are returned, never panics.
  • (*Stmt).Execute(args ...any) (Result, error) — bind and run; one Result per execution. Parameters map nil→NULL, bool, integer kinds (INTEGER/BIGINT), float32/64, string, time.Time (TIMESTAMP, µs), and pinkdb.Date (DATE). []byte is refused (no BLOB in ABI v1); native error strings are returned verbatim and the statement stays usable.
  • ParameterCount() / SQL() metadata; Close() is idempotent — later use returns ErrStmtClosed. A Stmt is safe for concurrent use (calls are serialized) and has no finalizer: call Close.

Result#

  • Kind: selected, created, inserted, updated, deleted, began, committed, rolledback, created_view, dropped_table, dropped_view, created_database, dropped_database, used, loaded_extension, checkpointed, altered_table, created_user, altered_user, dropped_user, created_role, dropped_role, granted, revoked.
  • Columns / ColumnTypes (SELECT only; types boolean, integer, bigint, double, varchar, date, timestamp), Rows.
  • Affected (INSERT/UPDATE/DELETE row count) and Name (view/table/database/USE name, or the extension name for LOAD EXTENSION; empty string when absent).

Errors and thread safety#

  • Native errors are returned verbatim (the message from pinkdb_last_error) and leave the handle usable. After Close, Execute fails fast with ErrClosed instead of touching freed memory.
  • DB serializes every native call behind a sync.Mutex, so one *DB may be shared between goroutines and each Execute is atomic with respect to the others. (The C handle itself is single-threaded; the native call and the error read are pinned to one OS thread, and result materialization happens after the thread is released.)
  • Close is idempotent; ABI() is library-wide and stays callable after close.

Testing#

Shell
cd bindings/go
gofmt -l .        # must print nothing
go vet ./...
go test ./...

Known limitation: ABI v1 reports column and object/session names as NUL-terminated C strings, so an identifier containing a NUL byte is truncated in Columns/Name (the engine keeps the full name internally). Avoid NUL bytes in identifiers until the engine-level fix lands.
