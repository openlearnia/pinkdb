Bindings

Use pinkdb from another language through the C ABI (pinkdb-ffi), or natively from Rust. Python and Go ship dependency-free wrappers over that same ABI.

LanguageMechanismStatusAPI reference
Rust the pinkdb library crate native Rust API →
C / C++ libpinkdb_ffi (cdylib + staticlib), ABI v1 shipped C API →
Python ctypes over the C ABI — no pip installs shipped Python API →
Go cgo over the C ABI shipped Go API →
anything with C interop drive pinkdb-ffi directly shipped C API →
JS / wasm, Node, Java — deferred (not scheduled yet) Roadmap →

Build the native library first

The Python and Go bindings, and any direct C use, need the shared library:

cargo build --release -p pinkdb-ffi
# -> target/release/libpinkdb_ffi.dylib  (or .so / .dll)
# -> target/release/libpinkdb_ffi.a      (static archive)

Nothing is added to the pinkdb binary. The C ABI is the only embedding crate that contains unsafe; the core stays zero-unsafe. Measured artifacts: libpinkdb_ffi.dylib ≈ 1.70 MB, libpinkdb_ffi.a ≈ 15.5 MB (build archive).

C ABI in one example

pinkdb_handle *db = pinkdb_open_memory();
const char *sql =
    "CREATE TABLE sales (region VARCHAR, total DOUBLE);"
    "INSERT INTO sales VALUES ('west', 10.5), ('east', 7.0);"
    "SELECT region, total FROM sales ORDER BY total DESC;";
pinkdb_result *result = pinkdb_execute(db, sql, strlen(sql));
/* ...read statement kinds, columns and pink_value cells... */
pinkdb_result_free(result);
pinkdb_close(db);

The full contract — handles, ownership, text lifetimes, threading — is in the C API reference. Handles are not thread-safe (use one per thread; serialize calls), and errors are thread-local (pinkdb_last_error()).

Python

import pinkdb

with pinkdb.connect_memory() as db:            # or pinkdb.connect("data.pink")
    db.execute("CREATE TABLE t (x INTEGER, s VARCHAR);")
    db.execute("INSERT INTO t VALUES (1, 'héllo'), (NULL, NULL);")
    result = db.execute("SELECT x, s FROM t ORDER BY x;")[0]
    print(result.kind, result.rows)  # selected [[1, 'héllo'], [None, None]]

Standard-library ctypes only; values map to Python types, errors raise pinkdb.Error. See the Python API.

Go

import pinkdb "github.com/openlearnia/pinkdb/bindings/go"

db, err := pinkdb.OpenMemory() // or pinkdb.Open("data.pink")
if err != nil {
    panic(err)
}
defer db.Close()

results, err := db.Execute(
    "CREATE TABLE t (x INTEGER, s VARCHAR);" +
        "INSERT INTO t VALUES (1, 'héllo'), (NULL, NULL);" +
        "SELECT x, s FROM t ORDER BY x;")
if err != nil {
    panic(err)
}
fmt.Println(results[2].Kind, results[2].Rows) // selected [[1 héllo] [<nil> <nil>]]

cgo and the Go standard library only; one *DB is safe to share between goroutines (calls are serialized). See the Go API.

Rust

Rust is the native interface — no ABI involved:

use pinkdb::PinkDb;

let mut db = PinkDb::new();
let results = db.execute("SELECT 40 + 2 AS answer;")?;

Start with the Rust API or the embedding guide.

A standalone Go module and a Python wheel are planned; today the Python package lives in bindings/python and the Go module is github.com/openlearnia/pinkdb/bindings/go.
