Bindings

Foreign-language access through the C ABI. The pinkdb-ffi crate is the only crate in the repo that contains unsafe; the core stays zero-unsafe.

C ABI (pinkdb-ffi)

The crate exposes the engine over a small C ABI as libpinkdb_ffi.dylib / libpinkdb_ffi.a for foreign bindings (Python cffi, Go cgo, …). The hand-written header lives at crates/pinkdb-ffi/include/pinkdb.h; the ABI version is 1 and queryable via pinkdb_abi_version(). Nothing is added to the pinkdb binary.

cargo build --release -p pinkdb-ffi
make -C crates/pinkdb-ffi hello   # compiles and runs the C example

Artifacts: libpinkdb_ffi.dylib ≈ 1.70 MB, libpinkdb_ffi.a ≈ 15.5 MB (build archive).

Contract

  • Handles: pinkdb_open (durable files), pinkdb_open_memory, and pinkdb_close. Handles are not thread-safe — use one per thread. Errors are thread-local: pinkdb_last_error() returns NULL when the last call on the calling thread succeeded.
  • Execute: pinkdb_execute(handle, sql, len) takes UTF-8 bytes (embedded NULs allowed) and returns a result that round-trips every statement kind and value type.
  • Results: per-statement kind tags (PINKDB_STMT_SELECTED, …_INSERTED, …), SELECT column names/types/rows, typed pink_value returned by value — with VARCHAR text borrowed from the result — plus affected counts and object/session names.
  • Ownership: free results with pinkdb_result_free, handles with pinkdb_close. Text pointers stay valid only until their owner is freed or the next FFI call on the same thread; copy them if you need them longer. The full contract (pointers, threading, text lifetimes) is in the header.
pinkdb_handle *db = pinkdb_open_memory();
const char *sql =
    "CREATE TABLE sales (region VARCHAR, total DOUBLE);"
    "INSERT INTO sales VALUES ('west', 10.5), ('east', 7.0);"
    "SELECT region, total FROM sales ORDER BY total DESC;";
pinkdb_result *result = pinkdb_execute(db, sql, strlen(sql));
/* …read kinds, columns, and pink_value cells… */
pinkdb_result_free(result);
pinkdb_close(db);
