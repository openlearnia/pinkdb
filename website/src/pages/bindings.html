Bindings

Use pinkdb from another language through the C ABI (pinkdb-ffi), or natively from Rust. Node, Python and Go ship wrappers over that same ABI, and all three run one shared conformance corpus.

Build the native library

Any direct C use, and the Python and Go bindings from a source checkout, need the shared library:

cargo build --release -p pinkdb-ffi
# -> target/release/libpinkdb_ffi.dylib  (or .so / .dll)
# -> target/release/libpinkdb_ffi.a      (static archive)

Nothing is added to the pinkdb binary. The C ABI is the only embedding crate that contains unsafe; the core stays zero-unsafe. Measured artifacts (release, macOS arm64): libpinkdb_ffi.dylib ≈ 3.5 MB, libpinkdb_ffi.a ≈ 26 MB (build archive).

A Python wheel bundles the shared library and a Node addon statically links it, so pip install and npm run build produce artifacts that need no separate library at run time. Go links the library (cargo build --release -p pinkdb-ffi, or PINKDB_LIB_DIR plus CGO_LDFLAGS outside a checkout).

C ABI in one example

pinkdb_handle *db = pinkdb_open_memory();
const char *sql =
    "CREATE TABLE sales (region VARCHAR, total DOUBLE);"
    "INSERT INTO sales VALUES ('west', 10.5), ('east', 7.0);"
    "SELECT region, total FROM sales ORDER BY total DESC;";
pinkdb_result *result = pinkdb_execute(db, sql, strlen(sql));
/* ...read statement kinds, columns and pink_value cells... */
pinkdb_result_free(result);
pinkdb_close(db);

The full contract — handles, ownership, text lifetimes, threading — is in the C API reference. Handles are not thread-safe (use one per thread; serialize calls), and errors are thread-local (pinkdb_last_error()).

Node.js

const { open } = require('@pinkdb/pinkdb');

const db = open('/tmp/data.pink');   // open() with no path is in-memory
db.run("CREATE TABLE t (i INTEGER, s VARCHAR)");
db.run("INSERT INTO t VALUES (?, ?)", [1, 'héllo']);
db.query('SELECT i, s FROM t WHERE i = ?', [1]);   // [{ i: 1, s: 'héllo' }]

for (const row of db.prepare('SELECT i FROM t ORDER BY i').iterate()) {
  console.log(row.i);
}
db.close();

A native addon built with napi-rs; run returns one result per statement, query returns row objects, prepare gives run/all/iterate, and errors are PinkdbError with a stable class. Build it with cd bindings/node && npm run build; the package is marked private (a npm pack tarball for local use, not a registry publish).

Python

import pinkdb

connection = pinkdb.connect_memory()   # or pinkdb.connect("data.pink")
cursor = connection.cursor()
cursor.execute("CREATE TABLE t (x INTEGER, s VARCHAR)")
cursor.executemany("INSERT INTO t VALUES (?, ?)", [(1, "héllo"), (2, None)])
cursor.execute("SELECT x, s FROM t ORDER BY x")
print(cursor.fetchall())               # [(1, 'héllo'), (2, None)]
connection.close()

Standard-library ctypes below a PEP 249 (DB-API 2.0) layer: connect/Connection/Cursor, paramstyle = "qmark", the exception hierarchy and the type objects. A wheel bundles the shared library (python3 -m pip wheel . --no-deps -w dist in bindings/python); the native Database/Statement API is still exported. See the Python API.

Go

import pinkdb "github.com/openlearnia/pinkdb/bindings/go"

db, err := pinkdb.OpenMemory() // or pinkdb.Open("data.pink")
if err != nil {
    panic(err)
}
defer db.Close()

results, err := db.Execute(
    "CREATE TABLE t (x INTEGER, s VARCHAR);" +
        "INSERT INTO t VALUES (1, 'héllo'), (NULL, NULL);" +
        "SELECT x, s FROM t ORDER BY x;")
if err != nil {
    panic(err)
}
fmt.Println(results[2].Kind, results[2].Rows) // selected [[1 héllo] [<nil> <nil>]]

cgo and the Go standard library only; one *DB is safe to share between goroutines (calls are serialized) and native errors are *pinkdb.Error with a stable Class. The module carries its own C declarations, so go get works without this checkout — only the library is needed at link time. See the Go API.

One conformance corpus

bindings/conformance/corpus.json is language-neutral: the Node, Python and Go bindings each run it in CI. It covers every SQL type's round trip (NULLs, extremes, unicode, DECIMAL, DATE/TIMESTAMP), positional parameters, stable error classes, transactions and autocommit, multiple and empty result sets, and a 100k-row case that the Node and Python bindings read one row at a time.

Rust

Rust is the native interface — no ABI involved:

use pinkdb::PinkDb;

let mut db = PinkDb::new();
let results = db.execute("SELECT 40 + 2 AS answer;")?;

Start with the Rust API or the embedding guide.

The Python wheel is not on PyPI and the Node package is not on npm yet: both build from bindings/ and are marked private. The Go module is github.com/openlearnia/pinkdb/bindings/go; JDBC, .NET and an ADBC driver are follow-ups on the roadmap.
