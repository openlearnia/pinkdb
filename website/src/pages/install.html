Install pinkdb

Prebuilt CLI binaries for Linux and macOS, published from v* tags. The installer is a plain shell script in this repository — download it, read it, then run it. It verifies the artifact against the release's SHA256SUMS before installing; nothing is piped into a shell.

Quick install

curl -fsSLO https://raw.githubusercontent.com/openlearnia/pinkdb/main/install.sh
sh install.sh

By default it installs the latest release's default CLI variant to ${PREFIX:-$HOME/.local}/bin/pinkdb. If that directory is not on your PATH, the script prints the export line to add. It never uses sudo.

verify first

The script fetches SHA256SUMS from the same release, requires an entry for the exact asset, and refuses on a mismatch. --dry-run prints the version, asset, URL and destination without downloading.

Choose a variant

The release matrix ships the same feature variants as the cargo builds. Pass --variant NAME (or set PINKDB_VARIANT):

VariantFeaturesWhat you get
defaultdefaultREPL, CSV import, .pink + WAL, json/datetime/math functions
lean--no-default-featuresthe same core without the linked json/datetime/math extensions
pinklakepinklake.lake over .pink data files
pinklake-s3pinklake,s3pinklake + s3:// storage (AWS S3, R2)
vortexlakevortexlake.lake over Vortex data files
vortexlake-s3vortexlake,s3Vortex lake + s3:// storage
 
sh install.sh --variant pinklake-s3
sh install.sh --variant vortexlake --prefix "$HOME/bin"

Pin a version

Without a version the installer asks GitHub for the latest release. Pin one with --version or PINKDB_VERSION; the asset is fetched from releases/download/v<version>/…:

sh install.sh --version 0.1.0
PINKDB_VERSION=0.1.0 sh install.sh --variant lean

Platform support

OSArchitecturesStatus
Linuxx86_64, aarch64published and smoke-tested per tag
macOSarm64, x86_64published and smoke-tested per tag (x86_64 cross-built on the arm runner)
Windows—not supported: no binary and no install.ps1 yet

The installer normalizes uname spellings (arm64 and aarch64 are the same asset architecture). Unsupported operating systems, architectures and variants fail with a clear message before any download.

Verify the download

Every release carries a SHA256SUMS manifest and a .sha256 sidecar for each tarball. To verify manually, download the manifest next to the asset and check it:

curl -fsSLO https://github.com/openlearnia/pinkdb/releases/download/v0.1.0/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS

Release assets and their names are immutable: a published name+version+platform is never overwritten. See the release guide for the full matrix, secret scoping and recovery rules, and the releases page for download links. This page is static and does not call the GitHub API at runtime.

Server binaries

The network server ships as separate tarballs on the same tag: pinkdb-server-<version>-<os>-<arch>-default (blocking transport), -async-server (tokio transport) and -tls (rustls). They contain the pinkdb-server binary; use the same SHA256SUMS to verify them. Install with your package manager or by unpacking the tarball; there is no server install script.

Build from source

If your platform or feature combination is not in the matrix, build it with cargo: see Getting started for the feature matrix and the release sizes.
