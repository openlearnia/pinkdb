Guide: CSV to a lake

Take a CSV file, shape it with SQL, publish it as an immutable lake snapshot, reopen it in a fresh process, and attach it read-only. Total time: a few minutes.

1. Build a lake-enabled CLI

# lean lake: .pink data files, 2.7 MB binary
cargo build --release -p pinkdb-cli --features lake-lite

# or the full lake: Vortex data files, 45.3 MB binary
cargo build --release -p pinkdb-cli --features lake
./target/release/pinkdb

2. Import the CSV

Any CSV works; the repository's deterministic generator produces a 1M-row sales file if you want something bigger:

python3 bench/gen_sales.py            # -> sales_1m.csv (~24 MB)
pinkdb> .import sales_1m.csv sales
Imported 1000000 rows in 0.025s

Check what was inferred and shape the table you want to publish:

pinkdb> .schema sales
pinkdb> SELECT region, COUNT(*) AS n, AVG(total) AS avg_total
   ...>   FROM sales GROUP BY region ORDER BY n DESC;

3. Save the lake

pinkdb> .lake save mylake
pinkdb> .lake info mylake
pinkdb> .lake versions mylake
pinkdb> .lake tables mylake

Each save is a full snapshot: fresh immutable data files, a new snapshots/<version>.json, then a replaced catalog.json. The first save of an empty store creates version 1 and publishes version 2 with your data.

4. Reopen in a fresh process

./target/release/pinkdb     # new process, empty store
pinkdb> .lake open mylake
pinkdb> SELECT COUNT(*) FROM sales;
pinkdb> .lake open mylake 2      -- an earlier published version, if you have one

.lake open replaces the in-memory store with a published version and resets the session database to main.

5. Attach read-only (the fast path)

pinkdb> .lake attach mylake
pinkdb> SELECT COUNT(*), MIN(total), MAX(total) FROM sales;  -- from stored statistics
pinkdb> .tables            -- lists sales (1000000 rows, attached)
pinkdb> .lake attached
pinkdb> .lake detach mylake

Attach decodes no column data for the statistics fast paths; anything else materializes the table lazily, decoding only the columns the query references. Attached tables are read-only and session-local.

Gotchas
  • Saving again rewrites every table — plan disk and time for full snapshots, not appends. Old versions and their files are kept; there is no GC.
  • .lake save, .lake open and .lake attach are refused inside a transaction.
  • A lean (lake-lite) build writes and reads only .pink data files; a lake saved by a full build (Vortex) is refused with a clear “rebuild with lake” error.
  • A second writer holding a stale handle gets another writer published version N; reopen the lake on save — or use .lake save in a fresh shell.
