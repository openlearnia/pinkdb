Guide: S3 / R2 lakes

Keep the catalog on local disk (or SQLite/Postgres) and the data files in S3, R2 or MinIO, using the SigV4 client behind the optional s3 feature.

1. Build with lake + S3

# .pink data files over object storage
cargo build --release -p pinkdb-cli --features pinklake,s3

# Vortex data files over object storage
cargo build --release -p pinkdb-cli --features vortexlake,s3
# `--features s3` alone adds the storage client but no `.lake` commands

2. Configure credentials

Everything comes from the environment — no profiles, no instance metadata. For Cloudflare R2:

export AWS_ACCESS_KEY_ID=<r2-token-key-id>
export AWS_SECRET_ACCESS_KEY=<r2-token-secret>
export AWS_ENDPOINT_URL=https://<account>.r2.cloudflarestorage.com
export AWS_REGION=auto

For AWS S3 the endpoint/region variables are optional. MinIO uses its endpoint plus path-style addressing (AWS_S3_FORCE_PATH_STYLE=1 forces it).

The bucket must already exist

pinkdb never creates buckets. An unknown bucket fails with the bucket does not exist (or is not visible to these credentials).

3. Save, list, reopen

The catalog is a database, so give it a location and point data at the bucket. A bare s3://… URL is only a data location.

pinkdb> .import sales_1m.csv sales
pinkdb> .lake save pink:/srv/lakes/demo.pink data s3://my-bucket/lakes/demo
pinkdb> .lake versions pink:/srv/lakes/demo.pink
pinkdb> .lake tables   pink:/srv/lakes/demo.pink
pinkdb> .lake info     pink:/srv/lakes/demo.pink
# a fresh process, catalog on disk and data in the bucket
./target/release/pinkdb

pinkdb> .lake open   pink:/srv/lakes/demo.pink
pinkdb> .lake attach pink:/srv/lakes/demo.pink
pinkdb> SELECT COUNT(*) FROM sales;   -- statistics fast path, 0 column decodes

For a lake shared by several machines, put the catalog in Postgres instead: .lake save postgres://user@host/db?schema=sales data s3://bucket/sales. Publication is one catalog transaction, so racing writers get the documented conflict/rebase behaviour without conditional object writes.

4. The same lake from Rust

use pink_lake::Lake;

let mut lake = Lake::create_with_catalog(
    "sqlite:/srv/lakes/demo.db",
    "s3://my-bucket/lakes/demo",
)?;
lake.write_from_store(&db)?;

let mut lake = Lake::open_with_catalog("sqlite:/srv/lakes/demo.db", None)?;
let tables = lake.tables()?;

Gotchas

  • One PutObject per data file — no multipart uploads, so one file must be ≤5 GiB; larger bodies are refused before sending. Old versions stay until .lake expire/cleanup.
  • Conditional object writes are gone. Only data files are written to S3; the catalog transaction is the single-writer guard, so an endpoint no longer needs conditional PUT support.
  • Retries are conservative. 429/503 are retried with backoff; a body is never replayed when the request may have succeeded.
