Everything in one small engine

Capabilities are opt-in cargo features, so you only pay for what you use — no crypto, TLS or format code lands in the default binary unless asked for.

  • Query engine

    • Embeddable

      Link the pinkdb crate and run SQL in-process — no daemon, no runtime dependencies.

    • Vectorized columnar core

      Typed column vectors in ≤2,048-row chunks; every operator runs over whole chunks, in parallel via rayon.

    • SQL surface

      DDL/DML, inner and outer equi-joins, CTEs, subqueries, window functions, aggregates and transactions.

    • CSV import

      One command infers the schema per column, parses in parallel, and detects DATE and TIMESTAMP.

  • Durable storage

    • Single-file .pink format

      Columnar v4 files with delta, dictionary, ALP and LZ encodings; bit-exact round trips and a CRC-32 guard.

    • WAL & crash recovery

      A durable open replays the write-ahead log, checkpoints atomically, and recovers interrupted checkpoints.

    • Multi-process writers

      Any local process may open a durable database read-write; writers serialize on a short write lease.

    • At-rest encryption

      Optional AES-256-GCM containers with Argon2id passphrase derivation, for checkpoints and the WAL.

  • Lake & object storage

    • Lake layer

      A JSON catalog plus immutable per-table snapshots, stored as Vortex or lean .pink v4 data files.

    • S3 / R2 lakes

      s3:// lakes on AWS S3, Cloudflare R2 or any S3-compatible endpoint, with conflict detection.

    • Read-only attach

      Open a published snapshot without decoding column data; exact COUNT/MIN/MAX come from stored statistics.

  • Integrations

    • C · Python · Go bindings

      A C ABI v1 with a hand-written header, plus dependency-free Python and Go wrappers — and Rust natively.

    • Network server

      pinkdb-server over TCP with a compact framed protocol and a remote CLI mode.

    • Loadable extensions

      Register scalar SQL functions from a shared library — or .install one from the catalog.

Honest by design

The SQL surface is deliberately small and growing in the open. Everything listed here is implemented and tested; what is queued lives on the roadmap, and the engineering log on GitHub has the detail.

Quickstart

Import, query, save — the whole loop takes a minute.

  1. Build the CLI

    The default build has no optional features.

    cargo build --release -p pinkdb-cli
./target/release/pinkdb

  2. Import and query

    Schema is inferred per column.

    .import sales.csv sales
SELECT region, AVG(total)
FROM sales GROUP BY region;

  3. Save it

    One durable, columnar file.

    .save sales.pink
.open sales.pink

At a glance

Numbers from the repository, measured on release builds.

Binaries default 2.44 MB · lean lake 2.69 MB · full lake 45.3 MB (release, Apple Silicon)
Persistence .pink v4 single-file columnar format; 1M rows → 2.68 MB, 10M rows → 26.8 MB
SQL CSV import, joins (INNER/LEFT/RIGHT equi), CTEs, subqueries, window functions, aggregates, CAST, dates; transactions and multi-database sessions
Durability write-ahead log + atomic checkpoints; durable databases are multi-process, with a 5 s busy timeout for writers
Lake catalog + immutable snapshots; Vortex or .pink v4 data files; read-only attach answers exact COUNT/MIN/MAX
Object storage s3:// locations on AWS S3, Cloudflare R2 or any S3-compatible endpoint (opt-in s3 feature)
Bindings Rust (native), C (ABI v1), Python (ctypes, no dependencies), Go (cgo)
Extensions loadable native scalar functions (ABI v1), C and Go SDKs, and a hosted extension catalog
DuckDB parity differentially tested against DuckDB on a committed query corpus; the current corpus matches on both engines
