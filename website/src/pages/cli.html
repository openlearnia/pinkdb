CLI & REPL

pinkdb-cli is a thin consumer of the library: a rustyline REPL with dot-commands and DuckDB-style box-drawn output. The release binary is named pinkdb.

Build and run

cargo run -p pinkdb-cli                        # debug REPL
cargo build --release -p pinkdb-cli
./target/release/pinkdb                        # local (embedded) mode

cargo build --release -p pinkdb-cli --features client
./target/release/pinkdb --host 127.0.0.1:5433  # remote mode (needs a server)

You land at the pinkdb> prompt. SQL statements run until a semicolon (a ...> continuation prompt appears while one is open); dot-commands are single-line and take no semicolon. Ctrl-C clears a pending statement; Ctrl-D and .quit leave the shell.

Command-line flags:

Usage: pinkdb [--host HOST:PORT] [--user NAME] [--password PASS] [-c COMMAND]...

  -c COMMAND         run SQL or a dot-command, then exit (repeatable)
  --host HOST:PORT   run as a client of a pinkdb-server (remote mode)
  --user NAME        log in as NAME (needs --password or PINKDB_PASSWORD)
  --password PASS    the login password (PINKDB_PASSWORD is the fallback)

Dot-commands

CommandDescription
.help show the dot-command help (a shorter list in remote mode)
.quit / .exit leave the shell
.read <file.sql> run SQL and dot-commands from a file in the current session
.timer on|off print each statement's run time (default: on in a terminal)
.databases list databases; the current one is marked and table/view counts are shown separately — main (current) (2 tables, 1 view)
.tables list tables (with row counts) and views of the current database; attached lake tables are marked
.schema <table|view> show a schema; accepts db.table, views show their output columns, and double-quoted identifiers with spaces work ("My Db".t)
.import <file.csv> [table] [key=value …] import a CSV; the table defaults to the file stem, and a db.table target names another database when db exists. Options are the read_csv ones below (sep=';' encoding=latin-1 header=true errors=warn …)
.save <file.pink> checkpoint when the path is the bound database, otherwise a plain snapshot (refused when the target has a sidecar WAL with committed records)
.open <file.pink> open durably: load the checkpoint, recover an interrupted checkpoint, replay the sidecar WAL, and replace the whole store
.lake save <dir|s3://…> [force] [author '<name>'] [message '<text>'] publish a full snapshot of the store, optionally recording the author and commit message on the new version; force overrides this session's stale-baseline conflict check
.lake open <dir|s3://…> [version] replace the in-memory store with a published lake version (latest by default)
ATTACH 'lake:<catalog>' AS name [(READ_ONLY, DATA '…', VERSION n)] SQL (wave 124): attach a lake as a database — read-only from its statistics, or writable (every committed statement publishes one incremental version); CREATE DATABASE name (TYPE LAKE, CATALOG '…') creates one, DETACH name forgets it, SHOW DATABASES lists storage and versions. The .lake attach/commit/detach/attached dot-commands are gone.
.lake partition <dir|s3://…> <table> by (col, bucket(N, col), …) | clear set (or clear) a table's partition spec — new writes split one data file per partition value set; spec changes never rewrite published files
.lake merge | rewrite <dir|s3://…> [table] maintenance: consolidate eligible data files (merge) or materialize heavily-deleted ones (rewrite) as one new version; published files are never mutated
.lake expire <dir|s3://…> expire old snapshots + commit deltas (by versions / older-than / keep-N; never the current version)
.lake cleanup | orphans <dir|s3://…> delete unreferenced data/ objects (dry-run/confirm + age gate; orphans bypasses the age gate)
.lake files | table_info | options | settings <dir|s3://…> introspection: per-file listing, table stats, lake options and settings
.lake versions <dir|s3://…> list the lake's published versions (the current one is marked)
.lake snapshots <dir|s3://…> list per-version records: time, author, message, counts and change summary
.lake tables <dir|s3://…> list the current version's db.table names and row counts
.lake info <dir|s3://…> show format version, current version, snapshots, commits and tables
.install <name[@version]> install an extension from a repository, verify its SHA-256, and load it (needs the repo feature)
.repositories [list | add <url> | remove <url>] manage the ordered repository list in $PINKDB_HOME/repositories.json (needs repo)
.installed list cached extension artifacts under $PINKDB_HOME (needs repo)

The .lake commands need a build with pinklake; without it they report this pinkdb binary was built without a lake feature. s3:// locations additionally need the s3 feature combined with the lake build (pinklake,s3 — s3 alone adds only the storage client). The .install/.repositories/.installed commands need the repo feature.

For .import, a dotted target is db.table only when the left side names an existing database — otherwise the whole string is the table name, so a file stem like data.2024.csv imports as data.2024.

CSV options

.import and read_csv share one option set (DuckDB's parameter names), so .import f.csv t sep=';' header=true and SELECT * FROM read_csv('f.csv', sep := ';', header := true) read a file identically — locally, over https:// and from s3://:

  • delimiter / sep / delim / separator — any single byte (a tab, or the \t spelling); quote — any byte; escape — a byte or off (the default).
  • encoding — utf-8 (default), latin-1, windows-1252, utf-16le, utf-16be; the default (auto) strips a UTF-8 BOM and switches to UTF-16 on a LE/BE BOM. Decoders stream, so remote read-ahead is unaffected.
  • header — auto (default) applies DuckDB's rule: infer over every row and again over the rows below the first, and treat row 1 as a header when the two disagree or the data is all text. true/false force it, names='x,y' overrides the names.
  • nullstr='NA,N/A' adds NULL tokens; allow_quoted_nulls=false keeps a quoted empty field as ''; force_not_null='a' keeps a column's empties as ''. By default an empty field is NULL whether quoted or not.
  • errors=warn (DuckDB's name for the same thing, ignore_errors := true) skips bad rows. .import prints a rejects report — line, column and reason, the first ten plus a total; a read_csv scan has nowhere to print that, so there a bad row is silently dropped. error is the default: the import fails, names the line, and leaves no table behind.
  • An import parses in parallel whenever a scan can prove the file's dialect (no \r, quotes only as RFC 4180 quoting — a quote opens a field, "" is a literal quote, a close is followed by a delimiter or a line end). Any other file goes through the streaming record reader, with the same schema and rows. read_csv scans use the same parser, window by window for a remote or large file, so a scan of a 773 MB lineitem.csv takes 1.4 s instead of 5.3 s.

Importing into a table that already exists matches columns by header name, case-insensitively: missing columns import as NULL, and file columns the table has no home for follow the error policy.

Output and timing

Results are box-drawn with a type row, then a row count and, in an interactive terminal, a timing line (.timer on|off toggles it):

┌─────────┬────────────┐
│ region  │ avg(total) │
│ VARCHAR │ DOUBLE     │
├─────────┼────────────┤
│ west    │ 175.0      │
│ east    │ 50.5       │
└─────────┴────────────┘
2 rows
Run Time (s): real 0.000

At most 10 000 rows are printed; longer results end with a (N more rows) note.

Agent mode

-agent switches the CLI into output meant for an AI agent driving it. It also turns on automatically when stdout is not a terminal and one of AI_AGENT, CLAUDECODE, CLAUDE_CODE, PI_AGENT, OPENCODE, CODEX_SANDBOX, CURSOR_AGENT or GEMINI_CLI is set. -no-agent and PINKDB_AGENT_MODE=0 force it off, a flag wins over the environment, and an interactive terminal never enables it by itself. One line on stderr announces the mode.

| region:VARCHAR | avg:DOUBLE |
|---|---|
| west | 175.0 |
| east | NULL |
… 1,234 more rows (1,284 total); 3 columns hidden: a, b, c

Results are compact Markdown tables with the type in each header, NULL for nulls and escaped control characters. The default caps are 100 rows, 32 columns and 500 characters per cell, and every truncation is reported with the hidden counts and the true totals. Errors are one line of JSON on stderr ({"error":"…","kind":"parse","position":6}); exit codes are unchanged.

A runaway-query guard (1,000,000 rows and 30,000 ms per statement by default) cancels a statement cleanly and leaves the session usable. A statement whose inputs total at least 100,000 estimated rows gets one cost hint on stderr naming the estimate and whether a remote scan is involved — it never blocks or prompts.

.help agent lists the mode, flags, caps and environment variables; .agent rows|cols|cell|budget|timeout|hint changes the display caps and budgets for the session. The defaults can also be set with PINKDB_AGENT_DISPLAY_ROWS, PINKDB_AGENT_DISPLAY_COLUMNS, PINKDB_AGENT_CELL_CHARS, PINKDB_AGENT_SCAN_ROWS, PINKDB_AGENT_TIMEOUT_MS and PINKDB_AGENT_HINT_ROWS (0 turns a cap, budget or hint off).

Scripting

Piped input and -c COMMAND (repeatable) follow sqlite3/duckdb conventions: errors go to stderr, there is no banner or timing, and a statement still open at end of input runs as if terminated. ; is recognized outside strings and comments (SELECT 1; -- note completes; SELECT ';' does not).

pinkdb -c ".open sales.pink" -c "SELECT COUNT(*) FROM sales;"
pinkdb < setup.sql || echo "setup failed"

Exit codes

CodeMeaning
0 success — and, in interactive mode, always when the shell exits normally
1 any statement or dot-command failed in a script run (piped stdin or -c), or a remote connection could not be established
2 usage error (unknown flag, missing value), a set-but-non-UTF-8 PINKDB_KEY, or --host in a build without the client feature

Environment variables

VariableEffect
PINKDB_KEY passphrase for at-rest encryption: .save writes encrypted and .open decrypts, and with the encryption feature the same key encrypts/decrypts .lake commands (save/open/attach/commit and friends). Must be valid UTF-8 — a set-but-invalid value exits 2 rather than silently writing plaintext; a keyless session refuses an encrypted lake (and a keyed session refuses a plaintext one), never guessing.
PINKDB_BUSY_TIMEOUT_MS how long .open and later statements wait for another process's write lease before reporting the database busy. Default: 5 s (5000).
PINKDB_TXN_RETRIES how many times a conflicting one-call transaction (BEGIN; …; COMMIT; as one input) is retried after a cross-process write conflict. Default 3; 0 reports the first conflict instead of retrying.
PINKDB_LAKE_* incremental-commit retry knobs: PINKDB_LAKE_MAX_RETRY_COUNT (default 10), PINKDB_LAKE_RETRY_BACKOFF (1.5) and PINKDB_LAKE_RETRY_WAIT_MS (100) — DuckLake's writer controls.
PINKDB_HOME where the extension cache and repository config live. Default: ~/.pinkdb.
PINKDB_REPO_ALLOW_HTTP allow a plain http:// repository URL outside loopback (local tests only; artifacts travel unencrypted).
PINKDB_S3_* S3/R2 tuning knobs (PINKDB_S3_ALLOW_HTTP, PINKDB_S3_ALLOW_DEGRADED, PINKDB_S3_RETRIES) and the AWS_* credential variables — see Lake. 
cargo build --release -p pinkdb-cli --features encryption
PINKDB_KEY='correct horse battery staple' ./target/release/pinkdb

Remote mode

With the optional client feature, --host HOST:PORT sends every SQL statement to a pinkdb-server and renders results with the same renderer and timing line. SQL (including USE, CREATE DATABASE and transactions) works unchanged; the file and catalog dot-commands (.import, .save, .open, .databases, .tables, .schema) report Error: <cmd> is not available in remote mode. Without the feature, --host is rejected with built without the client feature. PINKDB_KEY is inert in remote mode (the server's own at-rest configuration applies) and is reported as a warning instead of being silently ignored. Servers with users defined require credentials — --user/--password (or PINKDB_PASSWORD) log in before the first statement; a trusted server (empty catalog) needs none.
