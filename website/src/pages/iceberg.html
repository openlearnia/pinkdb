Iceberg tables

The iceberg extension reads Apache Iceberg v2 tables — the current snapshot or an older one — from local disk, https:// or s3://. It is opt-in (--features iceberg, which turns parquet on), and it uses the same remote transport as read_parquet.

Scanning a table

SELECT * FROM iceberg_scan('s3://bucket/sales');
SELECT * FROM iceberg_scan('warehouse/sales');            -- local table directory
SELECT * FROM iceberg_scan('warehouse/sales/metadata/v3.metadata.json');

-- time travel, with DuckDB's parameter names
SELECT * FROM iceberg_scan('warehouse/sales', snapshot_from_id := 1001);
SELECT * FROM iceberg_scan('warehouse/sales',
    snapshot_from_timestamp := TIMESTAMP '2026-10-01 00:00:00');

-- introspection
SELECT * FROM iceberg_snapshots('warehouse/sales');
SELECT * FROM iceberg_metadata('warehouse/sales');        -- live manifest entries
SELECT count(*) FROM iceberg_scan('warehouse/sales');     -- from the manifests

A directory resolves through metadata/version-hint.text and, when that is missing, through the newest metadata/vN.metadata.json. Paths recorded in the metadata resolve against the table root, so a table copied to another prefix — or served from a mock bucket in the tests — reads unchanged. That is what DuckDB calls allow_moved_paths, done always. A remote table needs the hint file: a directory cannot be listed over HTTP or S3, so pass the metadata file when there is none.

What a scan does

  1. Read the table metadata JSON and pick the snapshot.
  2. Read the snapshot's manifest list, drop manifests whose partition summaries cannot match the WHERE clause, and read the remaining manifests (Avro).
  3. Drop data files whose lower/upper bounds or NULL counts cannot match, and drop the DELETED entries.
  4. Apply positional delete files: their file_path/pos rows remove those positions from the matching data file.
  5. Read the surviving Parquet files through the Parquet reader, mapping each output column to a file column by field id.

Field-id mapping is what makes schema evolution work: a renamed column projects under its new name, and a column added later reads NULL in files written before it existed. iceberg_metadata reports the entries of the selected snapshot with DuckDB's column set (manifest_path, status, file_path, record_count, …), and iceberg_snapshots lists every snapshot in the metadata.

Remote reads

With the CLI's httpfs feature the extension reads through pinkdb-httpfs — the shared transport — with a 256 KiB read-ahead window over the metadata JSON and the Avro manifests, so a manifest is a couple of ranged requests instead of one whole-object fetch. The data files then use Parquet's ranged reader, so column-chunk coalescing, the opt-in range cache and the PINKDB_HTTPFS_PARALLELISM knob all apply. Credentials come from the same environment as every other remote read (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION, AWS_ENDPOINT_URL_S3).

Limits

  • Read-only: no INSERT, no commit, no catalog. Point the function at a table a writer already produced.
  • Positional deletes only. An equality delete file is refused with an error naming the file — DuckDB applies them; that is the follow-up.
  • v2 only: v1 metadata and a newer format version are refused at open with its number.
  • Partition pruning is identity-only: a bucket or truncate summary is ignored, never misapplied, so the scan stays correct and simply reads more files.
  • The Avro decoder handles the null and deflate block codecs; a table written with snappy or zstd blocks is refused by codec name.
  • One table per call: no remote globs or directories, and no MERGE/rewrite/maintenance.
