# pinkdb docs website

The pinkdb documentation site. It is a fully static, zero-dependency site
(no CDNs, no third-party requests of any kind; type is vendored and
self-hosted) generated by a small Python 3 stdlib-only script, and it deploys
to Cloudflare Workers static assets. One page — **Extensions** — ships a small
inline script that renders the extension catalog fetched at runtime from the
repository Worker
(`https://pinkdb-ext-repo.defaultcms.workers.dev/index.json`; the Worker
sends CORS `*` for it).

## Art direction — "soft data-zine"

The site reads like a warm-paper zine about data: paper `#F7F1E8`, warm ink
`#241F1C`, one desaturated pink accent `#C9557A` (plus ink blue `#2C4A66`
for links), warm-tinted greys only, a fixed paper-grain overlay, hard offset
shadows from a single top-left light source, dashed "cut lines", sticker
badges, tape strips, big section numerals, index-card code blocks, margin
notes, sketchy inline SVG diagrams, and a ticker strip on the landing and
Extensions pages.

Type is self-hosted (see `src/assets/fonts/README.md` for provenance and the
subsetting commands):

| Face | Role | File | Bytes |
|---|---|---|---|
| Bricolage Grotesque (variable) | display / headings | `fonts/bricolage-grotesque.woff2` | 35,852 |
| Public Sans (variable) | body text | `fonts/public-sans.woff2` | 23,928 |
| Public Sans Italic (variable) | body emphasis | `fonts/public-sans-italic.woff2` | 25,596 |
| JetBrains Mono (variable) | code, tables, data | `fonts/jetbrains-mono.woff2` | 28,156 |

All four are SIL Open Font License 1.1; the licence texts sit next to them.
`font-display: swap`, tabular numerals on every data surface, and every
animation is behind a `prefers-reduced-motion` guard.

## Build

```sh
python3 build.py
```

This wipes and regenerates `public/`:

- `pages/index.html` → `public/index.html`
- `pages/404.html` → `public/404.html`
- `pages/extensions.html` → `public/extensions.html` (so the page is served at `/extensions`)
- every other fragment → `public/docs/<name>.html`
- `src/assets/` → `public/assets/`

Fragments contain page content only. `src/layout.html` supplies the page
shell and uses these placeholders, filled by `build.py`:

| Placeholder | Filled with |
|---|---|
| `{{title}}`, `{{description}}` | per-page metadata (from `PAGES` in `build.py`) |
| `{{content}}` | the page fragment |
| `{{root}}` | relative path to the site root (`""` or `"../"`) |
| `{{nav-<key>}}` | active-link attributes on the matching page, empty elsewhere |
| `{{python-binding}}` | Python-binding section; reflects whether `bindings/python` exists |

The build fails if any `{{...}}` placeholder is left unexpanded. Fragments
without an entry in `build.py`'s `PAGES` map still generate under `docs/`
with a title derived from the file name.

## Preview locally

Use `wrangler dev` so the local preview matches production exactly (the site
links extensionless paths like `docs/sql`, which Workers' asset handling
resolves and a plain file server does not):

```sh
python3 build.py
wrangler dev          # then open the printed http://localhost:8787/
```

With a plain file server (`python3 -m http.server -d public`) only the
explicit `.html` paths (e.g. `docs/sql.html`) resolve, and the 404 page is
served plainly — useful for a quick look, not a faithful preview.

## Deploy to Cloudflare Workers

```sh
# from website/, with wrangler installed and authenticated
python3 build.py
wrangler deploy
# or just:
./deploy.sh
```

`wrangler.toml` serves the `public/` directory as static assets and uses
`not_found_handling = "404-page"`, so unknown paths return the generated
`404.html`.

Validate the deploy without publishing anything:

```sh
wrangler deploy --dry-run --outdir /tmp/pinkdb_docs_dry
```

## Content notes

- The pages mirror the repository README/ROADMAP/PLAN as of wave 26
  (Oct 2026): real feature lists, benchmark numbers, and binary sizes only.
  Keep it that way when editing — update the pages when the waves move.
- Content links to `github.com/openlearnia/pinkdb` are fine; do not add
  external stylesheets, scripts or image assets. Fonts live in
  `src/assets/fonts/` (self-hosted, OFL, licence texts committed) and are the
  only binary assets besides the generated favicon/OG images. The one
  deliberate exception to "no scripts" is `pages/extensions.html`, whose
  inline script fetches the extension catalog from the repository Worker
  (which sends CORS `*`) and renders it with the site's own CSS classes; keep
  that script inline too, and keep it the page's first `<script>` (the
  verifier lifts its pure section).
- Sketch diagrams are inline SVG (`<svg>` with `sk-*` classes defined in
  `style.css`) — no image files, and they scale/scroll instead of breaking
  the layout.

## Regenerating the raster assets

`src/assets/favicon.png` and `src/assets/og.png` are generated (and
committed) by a stdlib-only script with a tiny supersampled rasteriser:

```sh
python3 tools/make-assets.py
```

## Verifying the live site

After deploying (and after the repository Worker is deployed — the Extensions
page fetches it):

```sh
node verify-browser.mjs        # headless Chrome over the live docs + Worker
```

It renders `/extensions` in headless Chromium, exercises the filter, the
details hash route and the not-found state, checks the design system (fonts
load from the docs origin, active nav, readable text column, no third-party
requests, no horizontal overflow at 390px/1280px, reduced-motion handling),
loads the Worker `/` info page (palette, favicon, script-free, `/index.json`
from the page context with CORS `*`), and fails on any console error.
`ext-repo/worker/verify-ui.mjs` additionally checks the generated
`public/extensions.html` statically, asserts the vendored fonts + licences +
meta/OG/favicon on every page, and runs the lifted pure helpers against the
live catalog.
