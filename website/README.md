# pinkdb docs website

The pinkdb documentation site. It is a fully static, zero-dependency site
(no JavaScript, no external fonts/CDNs) generated by a small Python 3
stdlib-only script, and it deploys to Cloudflare Workers static assets.

## Layout

```
website/
├── build.py            # site generator (Python 3 stdlib only)
├── deploy.sh           # build + `wrangler deploy`
├── wrangler.toml       # Workers static-assets config (`./public` as the directory)
├── src/
│   ├── layout.html     # shared template with {{...}} placeholders
│   ├── assets/
│   │   └── style.css   # self-contained dark theme
│   └── pages/          # one HTML fragment per page
│       ├── index.html
│       ├── getting-started.html
│       ├── sql.html
│       ├── cli.html
│       ├── server.html
│       ├── persistence.html
│       ├── bindings.html
│       ├── architecture.html
│       ├── roadmap.html
│       └── 404.html
└── public/             # generated output (build.py writes this)
```

## Build

```sh
python3 build.py
```

This wipes and regenerates `public/`:

- `pages/index.html` → `public/index.html`
- `pages/404.html` → `public/404.html`
- every other fragment → `public/docs/<name>.html`
- `src/assets/` → `public/assets/`

Fragments contain page content only. `src/layout.html` supplies the page
shell and uses these placeholders, filled by `build.py`:

| Placeholder | Filled with |
|---|---|
| `{{title}}`, `{{description}}` | per-page metadata (from `PAGES` in `build.py`) |
| `{{content}}` | the page fragment |
| `{{root}}` | relative path to the site root (`""` or `"../"`) |
| `{{nav-<key>}}` | active-link attributes on the matching page, empty elsewhere |
| `{{python-binding}}` | Python-binding section; reflects whether `bindings/python` exists |

The build fails if any `{{...}}` placeholder is left unexpanded. Fragments
without an entry in `build.py`'s `PAGES` map still generate under `docs/`
with a title derived from the file name.

## Preview locally

Use `wrangler dev` so the local preview matches production exactly (the site
links extensionless paths like `docs/sql`, which Workers' asset handling
resolves and a plain file server does not):

```sh
python3 build.py
wrangler dev          # then open the printed http://localhost:8787/
```

With a plain file server (`python3 -m http.server -d public`) only the
explicit `.html` paths (e.g. `docs/sql.html`) resolve, and the 404 page is
served plainly — useful for a quick look, not a faithful preview.

## Deploy to Cloudflare Workers

```sh
# from website/, with wrangler installed and authenticated
python3 build.py
wrangler deploy
# or just:
./deploy.sh
```

`wrangler.toml` serves the `public/` directory as static assets and uses
`not_found_handling = "404-page"`, so unknown paths return the generated
`404.html`.

Validate the deploy without publishing anything:

```sh
wrangler deploy --dry-run --outdir /tmp/pinkdb_docs_dry
```
